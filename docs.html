Get started

Install the CLI

The open-source core runs anywhere Python does. One install, one command, and a verdict with evidence.

$ pip install lunas-validator
$ lunas check ./my-project

# example output
structure & imports .... PASS
install & compile ...... PASS
tests .................. FAIL (2)
verdict: NOT READY  · details in lunas-report.json

A non-zero exit code on failure makes the CLI drop straight into CI: add one line to your pipeline and unverified code stops merging.

Needs Python 3.11 or newer. Node.js is used when it is present, for the JavaScript syntax check and npm ci; without it those checks are skipped and say so.

Get started

First scan

Point the CLI at a directory. It reads the files, resolves every import and route, installs dependencies, compiles what compiles and runs the tests it finds. Nothing leaves your machine.

$ lunas check ./my-project --json lunas-report.json --exit-on-fail

Options

--json PATHWrite the full report as JSON next to the console output.
--exit-on-failExit with code 1 when the verdict is a fail. Without it the CLI exits 0 unless it crashed.
--no-llmSkip the two checks that ask a model (design fidelity, feature coverage). No API key needed; the default in CI.
--brief PATHA brief.json describing what was asked for. Enables the feature coverage and design fidelity checks.
--verbose, -vPrint one line per check with its summary.

Without a brief and an ANTHROPIC_API_KEY the two model-assisted checks are skipped and reported as skipped. The other 19 are deterministic: same input, same verdict.

Get started

Web scans

Sign in with Google or an email link, upload a zip or point Lunas at a repository, and read the report in the app. A Core scan takes about a minute. A Full scan boots the project in a fresh sandbox and takes about four.

  • Three Core scans a month are free. No card.
  • Full scans come from a plan, or one at a time as pay as you go. Pricing is inside the app under Settings.
  • The sandbox is destroyed when the scan ends. The report, the badge and the public page stay until you delete them.
  • A passed Full scan gives the project a badge for the README and a public verification page.

Guides

CI integration

Run Core on every push. The job fails when the verdict is a fail, and the JSON report is there for the log.

# .github/workflows/lunas.yml
name: lunas
on: [push, pull_request]
jobs:
  core:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - run: pip install lunas-validator
      - run: lunas check . --no-llm --exit-on-fail --json lunas-report.json

Keep the report in your account

A report produced in CI can be sent to Lunas so it shows up next to your web scans. It uses no web quota and never touches a sandbox; the code stayed where it was. Create a token under Settings › Connections and store it as a secret.

      - run: |
          jq -n --arg p "$GITHUB_REPOSITORY" --arg c "$GITHUB_SHA" --slurpfile r lunas-report.json \
            '{project: $p, commit: $c, report: $r[0]}' \
          | curl -sS -X POST https://lunas.novesteria.com/api/reports \
              -H "Authorization: Bearer $LUNAS_TOKEN" -H "Content-Type: application/json" -d @-

Full scans, the badge and the GitHub check come from the app: connect the repository under Settings › Connections and turn on scan on push.

Guides

Reading a report

Every report has the same shape: a verdict on top, then groups of checks, then the failures with what was seen.

  • The verdict is pass or fail. There is no partial. 74 of 75 is a fail with one named reason.
  • Groups tally the checks in an area: structure and imports, install and compile, contract and schema, runtime behavior. Core reports cover the first two and the tests.
  • A failure names the check, says in plain words what was expected and what was found, and quotes the evidence: the file and line, the command output, or the request and response.
  • Skipped checks are listed as skipped with the reason, for example no tests, no tsconfig, or no Node.js on the machine.

In the app the report can be downloaded as Markdown or JSON, and every earlier scan of the project stays reachable from the project page. The JSON written by the CLI carries the same fields: passed, layers with a verdict and summary each, and the evidence.

Reference

Check reference

The 21 checks in the open-source core, by name as they appear in the JSON report. The source is public, so what a pass means is never a secret.

Structure and imports

python_importsEvery local Python import resolves to a file in the repository.
python_completenessNo stub function bodies left in Python code.
static_importsRelative imports and script or stylesheet references exist on disk.
named_import_consistencyNamed imports from relative paths resolve to a real export.
import_case_consistencyImport paths match file names and exports in casing.
duplicate_type_declarationsNo duplicate interface or type declarations with differing shapes.
hook_destructure_consistencyHook consumers destructure only fields the hook returns.
react_prop_consistencyJSX prop usage matches the component's declared props.
router_prefix_consistencyFastAPI routers are not mounted with a doubled prefix.
html_js_id_parityEvery element id the JavaScript reaches for exists in some HTML file.
interactivityInteractive HTML has at least one JavaScript event handler.
css_completenessCSS files contain real rules, not placeholders.
ast_brace_balanceBraces, parentheses and brackets balance in JavaScript and TypeScript.

Install and compile

python_deps_completenessThird-party Python imports are declared in the project's dependencies.
node_deps_completenessBare-specifier Node imports are declared in package.json.
js_syntaxnode --check over every JavaScript file.
npm_installnpm ci, or npm install, on the project root.
tsctsc --noEmit type check; skipped when there is no tsconfig.json.

Tests

pytestpython -m pytest; skipped cleanly when there are no tests.

With a brief

feature_coverageKeyword scan plus a model's judgement on whether the asked-for features are present. Needs a brief and an API key.
design_fidelityA model's judgement of design-brief fidelity with a deterministic override. Needs a brief and an API key.
Reference

Exit codes

0The scan ran. With --exit-on-fail this also means the verdict was a pass.
1The verdict was a fail and --exit-on-fail was set.
2The CLI could not run: the path is not a directory, the brief did not load, or the command was not recognised.

Warnings, for example a model client that could not be created, go to stderr and do not change the exit code.
