How it works

Two engines, one question: does it work as asked.

Core is open source and runs anywhere. Full takes the same project into a fresh sandbox, boots it and probes what it does. Both end in a pass or a fail, with the evidence behind it.

01 · ReadThe commit, and nothing else

A repository at one commit, or a zip you upload. Read into a sandbox, never into storage.

02 · CoreStructure, install, compile

21 deterministic checks. Every file, import and route resolves; dependencies install; the project compiles. Free, open source, about a minute.

03 · FullBoot it, audit it, probe it

75 checks. The app is started cold, frontend and backend are held to the same contract, and the behavior you asked for is exercised. About four minutes.

04 · VerdictPass or fail, named

Every failure has a name and its evidence. The report is kept, the badge updates, GitHub gets one check.

Core is the floor. Full is the proof.

Core tells you the project is well-formed. Full tells you it runs and does what the plan says. Same report shape, same badge shape, different depth.

The GitHub check

One line on every push or pull request. The app reads code at one commit and writes that line. It never pushes.

We never keep code

The sandbox is destroyed when the scan ends. The report is the only thing that stays.

We never list the layers

You see the four groups and the named failures. The checks themselves are not a menu to game.

We never say "mostly"

74 of 75 is a fail with one named reason. The badge only exists for a pass.
